# Communication style

The user is learning (MLOps/AIOps, this codebase, and related concepts) alongside building it. When explaining anything - a concept, a tool, why something broke, what a piece of code does - default to simple, plain-language explanations:

- Avoid unexplained jargon; when a technical term is necessary, define it in one short clause the first time it's used.
- Prefer short sentences and concrete examples over abstract descriptions.
- Say what something *is* and *why it matters* before diving into *how* it works internally.
- This applies to chat replies, code comments, and notebook markdown cells alike.

This doesn't mean dumbing down technical correctness - it means explaining real technical content in the simplest language that doesn't lose accuracy.
